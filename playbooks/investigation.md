# Investigation

**You own the answer. Plan, route, write.** Read-only: the output is a cited explanation or a recommendation, never a code change.

1. Route through `/shinstack:how`. For "why is it like this" questions, also `/shinstack:why`.
2. Produce the `how`-shaped output (Overview, Key Concepts, How It Works, Where Things Live, Gotchas), or a recommendation with a tradeoffs table when the request is a choice between alternatives.
3. Run the reply through `/shinstack:unslop`.

No PR, no babysit. If the investigation precedes a code change, hand back and re-route to `bug-fix.md` or `feature.md`.

**Reply:** the investigation output. For "are we sure?" questions, give your real judgment with reasons, and push back if the premise is wrong.
